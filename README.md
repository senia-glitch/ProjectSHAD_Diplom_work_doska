# Доска

Совместная доска для рисования в реальном времени. Создаёте доску, отправляете ссылку, и все, у кого она есть, рисуют одновременно. Каждый видит чужие штрихи по ходу рисования и курсоры с именами. Рисунки хранятся в PostgreSQL: после перезапуска сервера и для новых участников доска остаётся на месте.

Стек: Python 3.14, event-infra + core-package + fastbase (FastAPI/uvicorn), PostgreSQL 17, интерфейс на чистом JS/Canvas.

## Возможности

- Доступ по ссылке `/b/<id>`. Идентификатор — случайный токен из 128 бит, его нельзя подобрать. Ссылка и есть ключ доступа: регистрации нет.
- Инструменты: карандаш, линия, прямоугольник, эллипс (с Shift — квадрат, круг, линия под 45°), ластик, перемещение. Восемь цветов и свой цвет, четыре толщины.
- Отмена и повтор своих штрихов (Ctrl+Z, Ctrl+Shift+Z); чужие отменить нельзя. Очистка всей доски с подтверждением.
- Масштаб: Ctrl+колесо, щипок двумя пальцами, кнопки «−»/«+». Перемещение: колесо, пробел+перетаскивание, средняя кнопка мыши, инструмент «рука». Есть «Показать всё» (F) и экспорт в PNG.
- Участники в шапке, их курсоры на холсте, уведомления о входе.
- Автоматическое переподключение. Штрихи, которые не успели дойти до сервера, отправляются повторно.
- Тёмная и светлая темы, раскладка для телефона (панель снизу).

## Установка (Windows, один раз)

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-tested.txt
.venv\Scripts\python.exe -m scripts.configure
docker compose up -d db --wait
.venv\Scripts\python.exe -m scripts.migrate --database doska
```

`scripts.configure` создаёт локальный `.env` с паролями, существующий файл не трогает. БД слушает только `127.0.0.1:15442`.

## Проверка в локальной сети

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-lan.ps1
```

Скрипт выводит адреса вида `http://192.168.1.151:8090`. Откройте такой адрес на телефоне или другом компьютере в той же сети, создайте доску и отправьте ссылку остальным. Порт меняется параметром `-Port 9000`.

Если с других устройств страница не открывается, разрешите входящие подключения на порт в брандмауэре Windows. Это делается один раз, в PowerShell от имени администратора, только для частной сети:

```powershell
New-NetFirewallRule -DisplayName "Doska 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow -Profile Private
```

В LAN доска работает по обычному `http://`. Браузер считает такой адрес незащищённым, поэтому для копирования ссылки и генерации ключей используются совместимые запасные способы.

## Развёртывание на сервере (интернет)

Схема: nginx (HTTPS, домен) → приложение в Docker на `127.0.0.1:18090` → PostgreSQL в Docker. Страница, открытая по `https://`, сама подключается к WebSocket по `wss://`.

1. Установите Docker и nginx, направьте домен на сервер, получите сертификат (например, `certbot`).
2. Скопируйте проект и создайте `.env`. Удобнее всего так: `python3 -m scripts.configure` (нужны `python-dotenv` и `sqlalchemy`), либо вручную по `.env.example`. Укажите адрес сайта:
   `BOARD_ALLOWED_ORIGINS=https://board.example.com`
3. Соберите образ, примените миграции, запустите:
   ```bash
   docker compose -f compose.yaml -f compose.prod.yaml build app
   docker compose -f compose.yaml -f compose.prod.yaml run --rm migrate
   docker compose -f compose.yaml -f compose.prod.yaml up -d app --wait
   ```
4. Подключите [deploy/nginx.conf](deploy/nginx.conf): замените домен, создайте `/etc/nginx/doska-proxy.conf` по комментарию в конце файла, выполните `nginx -t && systemctl reload nginx`. Без заголовков `Upgrade`/`Connection` WebSocket через nginx работать не будет.
5. Проверка: `curl https://board.example.com/api/v1/ready` → `{"status":"ready"}`.

Резервная копия: `docker compose exec db pg_dump -U factory doska > doska-$(date +%F).sql`. Восстановление: `psql` в пустую БД, затем `scripts.migrate`.

## Безопасность и ограничения

Что уже сделано для работы в интернете:

- WebSocket принимает подключения только со страниц своего сайта (проверка `Origin`; список задаётся в `BOARD_ALLOWED_ORIGINS`).
- Лимиты (настраиваются в `.env`, см. `.env.example`): участников на доску — 50, штрихов на доску — 20 000, сообщений в секунду от клиента — 60, размер сообщения — 256 КБ, новых досок с одного адреса — 20 в минуту. Медленный клиент, который не успевает читать, отключается и не раздувает память сервера.
- Все данные штрихов проверяются на сервере: инструмент, цвет, толщина, число и диапазон координат.
- Заголовки: CSP (только свои скрипты и подключения), `Referrer-Policy: no-referrer` (ссылка-ключ не уходит сторонним сайтам), `X-Frame-Options: DENY`. Документация API (`/docs`) отключена.
- Порт приложения в Docker открыт только на `127.0.0.1`; снаружи доступен лишь nginx.

Ограничения:

- Доступ «по ссылке». Любой, у кого есть ссылка, может рисовать и очищать доску; ролей «только просмотр» и владельца нет. Отозвать ссылку нельзя, можно только создать новую доску.
- Комнаты держатся в памяти одного процесса (`FAT_WORKERS=1`). Одного процесса хватает на много досок: на одной доске проверено 40 одновременных участников, каждый получил все штрихи остальных быстрее чем за секунду. Для нескольких процессов или серверов понадобится общая шина сообщений (PostgreSQL LISTEN/NOTIFY или Redis).
- Ластик стирает пиксели, а не удаляет штрихи. Он тоже штрих и отменяется как штрих.

## Разработка

```powershell
.venv\Scripts\python.exe -m scripts.check
.venv\Scripts\python.exe -m scripts.check --integration --database doska_test
```

Интеграционные тесты работают только с отдельной тестовой БД `doska_test` и проверяют HTTP API, совместное рисование через WebSocket, отмену, очистку, сохранность после переподключения и отказы (несуществующая доска, чужой Origin, неверное приветствие).

Структура:

| Путь | Назначение |
|---|---|
| `app/scenarios/boards.py` | бизнес-сценарии core: доски, штрихи, готовность БД |
| `app/api/v1/routes/boards.py` | HTTP API и WebSocket `/api/v1/boards/{id}/ws` |
| `app/realtime/hub.py` | комнаты, рассылка, лимиты частоты |
| `app/access.py`, `config/access.toml` | единая политика доступа (роль `guest`) |
| `models.py`, `alembic/versions` | схема БД и ревизии миграций |
| `frontend/` | главная (`index.*`) и доска (`board.*`), стиль `styles.css` |

Протокол WebSocket (JSON): клиент отправляет `hello` → получает `init` (снимок доски и участники), затем `draw` (живые части штриха, не сохраняются), `stroke` (готовый штрих), `remove`, `clear`, `cursor`, `rename`, `ping`. Сервер рассылает `join`/`leave`/`peer`, `draw`, `stroke`, `remove`, `clear`, `cursor`, `reject`, `error`. Коды закрытия: `4404` — доски нет, `4429` — доска переполнена, `1008` — нарушение протокола или лимита частоты, `1009` — слишком большое сообщение.

Миграции при старте приложения не применяются: сервер только проверяет, что схема актуальна. Новые изменения схемы оформляются ревизией в `alembic/versions` и применяются через `scripts.migrate`.
