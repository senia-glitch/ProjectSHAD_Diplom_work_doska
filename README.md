# Доска

Совместная доска для рисования в реальном времени: до 15 участников, вход по ссылке и коду, общий чат. Пока на доске есть люди, она живёт в памяти сервера. Сервер сохраняет её в PostgreSQL каждые N минут и когда уходит последний участник. Позже на доску можно вернуться по той же ссылке и коду.

Стек: Python 3.14, event-infra + core-package + fastbase (FastAPI/uvicorn), PostgreSQL 17, интерфейс на чистом JS/Canvas.

## Возможности

- **Вход по ссылке и коду.** Ссылка `/b/<id>` содержит случайный идентификатор из 128 бит. Код входа создатель задаёт сам (4–32 буквы или цифры) или получает сгенерированный (8 символов, например `8P4H5XYU`). Регистр, пробелы и дефисы в коде не важны. Сервер хранит только хеш кода (scrypt), поэтому создатель видит код один раз, при создании, и сразу получает окно «Пригласить» со ссылкой и кодом. Браузер запоминает код, и повторно вводить его не нужно.
- **Штрих отправляется только целиком.** Пока участник рисует, линия видна только ему; другие получают её одним сообщением после отпускания. Курсоры участников передаются не чаще 10 раз в секунду, и сервер рассылает их пачками.
- **Инструменты:** карандаш, линия, прямоугольник, эллипс (с Shift — квадрат, круг, линия под 45°), ластик, перемещение. Восемь цветов и свой цвет, четыре толщины.
- **Отмена и очистка.** Отмена и повтор своих штрихов (Ctrl+Z, Ctrl+Shift+Z), чужие отменить нельзя. Очистка всей доски с подтверждением.
- **Масштаб и навигация:** Ctrl+колесо, щипок двумя пальцами, кнопки «−»/«+», «Показать всё» (F).
- **Общий чат доски.** Хранятся последние 300 сообщений. Enter отправляет, Shift+Enter переносит строку. Пока чат закрыт, на кнопке растёт счётчик непрочитанных.
- **Индикаторы** в шапке:
  - заполненность доски: процент от лимита по числу штрихов или по объёму, смотря что больше; при 70% индикатор жёлтый, при 90% красный;
  - участники «N/15»;
  - состояние сохранения: «Сохранено в 13:55» или «Есть несохранённые изменения».
- **Индикаторы чата:** счётчик истории «N/300»; счётчик символов, когда сообщение приближается к лимиту в 1000 символов.
- **Файл доски** (меню «Файл доски» в шапке), без чата:
  - выгрузить в `.doska.json`;
  - загрузить из файла: добавить к рисунку или заменить его;
  - сохранить картинку (PNG).
- **Новая доска из файла:** кнопка «Из файла…» на главной.
- **Переподключение** автоматическое. Штрихи, которые не успели дойти до сервера, отправляются повторно.
- Тёмная и светлая темы, раскладка для телефона.

### Жизненный цикл доски

1. **Создание.** `POST /api/v1/boards` записывает доску и хеш кода в БД.
2. **Вход первого участника.** Сервер проверяет код и поднимает доску из БД в память процесса.
3. **Работа.** Изменения применяются в памяти и сразу рассылаются участникам. Автосохранение раз в `BOARD_AUTOSAVE_MINUTES` минут (по умолчанию 2) записывает снимок, если доска изменилась.
4. **Уход последнего участника.** Доска сохраняется и выгружается из памяти.
5. **Остановка сервера.** Сохраняются все открытые доски, клиенты переподключаются.
6. **Удаление.** Доски, на которые не заходили `BOARD_RETENTION_DAYS` дней (по умолчанию 30), удаляются вместе со штрихами и чатом.

При аварийном завершении процесса (`kill -9`, сбой питания) теряются изменения с последнего автосохранения, то есть не больше N минут.

### Формат файла доски

Обычный JSON, его можно открыть в любом редакторе. Каждый штрих записан одной строкой, чата в файле нет:

```json
{
  "format": "doska",
  "version": 1,
  "title": "План спринта",
  "exported_at": "2026-11-24T13:15:45+03:00",
  "strokes": [
    {"tool":"rect","color":"#e5484d","width":4,"pts":[-200,-80,-40,60]},
    {"tool":"pen","color":"#1f2430","width":2,"pts":[0,0,10,12,20,15]}
  ]
}
```

- `tool`: `pen`, `line`, `rect`, `ellipse` или `eraser`.
- `pts`: плоский список координат `x, y` в единицах доски. Для фигур это два угла.

Выгрузку собирает браузер участника из текущего состояния доски. Загрузка требует код доски. Сервер проверяет каждый штрих: если файл повреждён или не помещается в лимит, доска не меняется.

## Установка (Windows, один раз)

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-tested.txt
.venv\Scripts\python.exe -m scripts.configure
docker compose up -d db --wait
.venv\Scripts\python.exe -m scripts.migrate --database doska
```

`scripts.configure` создаёт локальный `.env` с паролями и не трогает существующий файл. БД слушает только `127.0.0.1:15442`.

## Проверка в локальной сети

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run-lan.ps1
```

Скрипт выводит адреса вида `http://192.168.1.151:8090`. Порт меняется параметром `-Port 9000`. Чтобы другие устройства в сети могли зайти:

1. Откройте адрес по IP, не через `localhost`, иначе ссылка в приглашении будет на `localhost`.
2. Создайте доску.
3. Отправьте участникам ссылку и код из окна «Пригласить».

Если с других устройств страница не открывается, разрешите порт в брандмауэре Windows. Команду нужно один раз запустить в PowerShell от имени администратора; правило действует только для частной сети:

```powershell
New-NetFirewallRule -DisplayName "Doska 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow -Profile Private
```

## Развёртывание на сервере (интернет)

Схема:

```
nginx (HTTPS) ─ hash(board_id) ─┬─> app   127.0.0.1:18090 ─┐
                                └─> app-2 127.0.0.1:18091 ─┴─> PostgreSQL
```

Каждая доска живёт в памяти ровно одного процесса. nginx выбирает процесс по идентификатору доски из адреса (`hash … consistent`), поэтому все участники доски попадают в один процесс, а разные доски распределяются между процессами. Общая шина между процессами не нужна.

1. Установите Docker и nginx, направьте домен на сервер, получите сертификат (например, `certbot`).
2. Скопируйте проект и создайте `.env`: `python3 -m scripts.configure` (нужны `python-dotenv` и `sqlalchemy`) или вручную по `.env.example`. Укажите адрес сайта:
   `BOARD_ALLOWED_ORIGINS=https://board.example.com`
3. Соберите образ, примените миграции, запустите процессы:
   ```bash
   docker compose -f compose.yaml -f compose.prod.yaml build app
   docker compose -f compose.yaml -f compose.prod.yaml run --rm migrate
   docker compose -f compose.yaml -f compose.prod.yaml up -d app app-2 --wait
   ```
4. Подключите [deploy/nginx.conf](deploy/nginx.conf):
   - замените домен;
   - создайте `/etc/nginx/doska-proxy.conf` по комментарию в конце файла;
   - выполните `nginx -t && systemctl reload nginx`.

   Без заголовков `Upgrade`/`Connection` WebSocket работать не будет. Без `Host $http_host` проверка `Origin` отклонит подключения на нестандартном порту.
5. Проверка: `curl https://board.example.com/api/v1/ready` → `{"status":"ready"}`.

**Ещё один процесс.** Скопируйте `app-2` в `compose.prod.yaml` как `app-3` с портом `APP_PORT_3` и добавьте `server 127.0.0.1:<порт>` в `upstream doska_app`. Число процессов меняйте только с перезапуском всех: при остановке процессы сохраняют свои доски, а после смены числа часть досок переедет в другой процесс.

**Обновление версии:** `build`, затем `migrate`, затем `up -d app app-2`. Остановка процесса сохраняет его доски (`stop_grace_period: 30s`), клиенты переподключаются за несколько секунд.

**Резервная копия:** `docker compose exec db pg_dump -U factory doska > doska-$(date +%F).sql`. Открытые доски попадают в копию в состоянии последнего автосохранения.

## Безопасность и ограничения

Защита входа:

- **Вход требует ссылку и код.** Неверный код закрывает соединение с кодом `4401`.
- **Перебор с одного адреса.** 10 неверных кодов за 15 минут по любым доскам блокируют адрес на 15 минут (`4408`, в причине закрытия `retry:<секунды>`). Клиент показывает обратный отсчёт.
- **Распределённый перебор одной доски.** 30 неверных кодов за 15 минут с разных адресов блокируют вход на доску для новых адресов. Адреса, которые уже входили на неё успешно, проходят.
- **Спам подключениями:** не больше 30 подключений в минуту с одного адреса в приложении и 60 в минуту в nginx.
- **Участники:** не больше 15 на доску (`4429`).

Остальное:

- **Чужой сайт.** WebSocket принимает подключения только со страниц своего сайта (проверка `Origin`, список в `BOARD_ALLOWED_ORIGINS`).
- **Ключ автора скрыт.** Участникам рассылается не секретный ключ автора, а его хеш (`by` у штриха, `tag` в чате). Чужой штрих нельзя удалить, выдав себя за автора.
- **Лимиты** (настраиваются в `.env`, см. `.env.example`):
  - 20 000 штрихов на доску и 2 млн координат суммарно;
  - 40 сообщений в секунду от клиента, сообщение до 256 КБ;
  - чат: до 1000 символов, в среднем сообщение в секунду (серия до 5);
  - файл доски до 16 МБ, не больше 10 загрузок в минуту.
- **Медленный клиент.** Клиент, который не успевает читать, отключается и не раздувает память сервера.
- **Заголовки.** CSP, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`; документация API (`/docs`) отключена.
- **Порты.** Порты приложения в Docker открыты только на `127.0.0.1`; снаружи доступен лишь nginx.

Ограничения:

- **Права.** Любой участник может очистить доску или заменить её файлом. Ролей «только просмотр» нет. Сменить код существующей доски нельзя.
- **Одна доска — один процесс.** Потолок одной доски — 15 участников; процессы добавляются ради числа досок.
- **Старые доски.** Доски, созданные до появления кодов, не открываются: у них нет кода. Они удалятся по сроку хранения.

## Разработка

```powershell
.venv\Scripts\python.exe -m scripts.check
.venv\Scripts\python.exe -m scripts.check --integration --database doska_test
```

Интеграционные тесты работают только с отдельной тестовой БД `doska_test`.

Структура:

| Путь | Назначение |
|---|---|
| `app/scenarios/boards.py` | правила данных, код входа (scrypt), сценарии core: создание, проверка кода, загрузка/сохранение снимка, очистка |
| `app/realtime/hub.py` | доски в памяти: участники, штрихи, чат, курсоры пачками, автосохранение, выгрузка |
| `app/realtime/guard.py` | защита входа: частота подключений, перебор кода по адресу и по доске |
| `app/api/v1/routes/boards.py` | HTTP API и WebSocket `/api/v1/boards/{id}/ws` |
| `app/access.py`, `config/access.toml` | единая политика доступа (роль `guest`) |
| `models.py`, `alembic/versions` | схема БД и ревизии миграций |
| `frontend/` | главная (`index.*`) и доска (`board.*`), стиль `styles.css` |

**HTTP API:**
- `POST /api/v1/boards` с телом `{title, author, code?}` → `{id, title, code, created_at}`;
- `POST /api/v1/boards/{id}/import` с телом `{mode: "append"|"replace", author, name, code, board: <файл>}`.

**Протокол WebSocket (JSON).**
- Клиент отправляет:
  - `hello` с полями `{author, name, code}`; в ответ приходит `init` (снимок доски, участники, чат, лимиты, `savedAt`);
  - затем `stroke` (готовый штрих), `remove`, `clear`, `cursor`, `chat`, `rename`, `ping`.
- Сервер рассылает: `join`/`leave`/`peer`, `stroke`, `remove`, `clear`, `cursors` (пачка `[[id, x, y], …]`), `chat`, `import`, `saved`, `reject`, `error`, `pong`.
- Коды закрытия:
  - `4401` — неверный код;
  - `4404` — доски нет;
  - `4408` — блокировка входа (`retry:<с>`);
  - `4429` — доска заполнена;
  - `1008` — нарушение протокола или лимита частоты;
  - `1009` — слишком большое сообщение;
  - `1012` — перезапуск сервера.

Миграции при старте приложения не применяются: сервер только проверяет, что схема актуальна. Изменения схемы оформляются ревизией в `alembic/versions` и применяются через `scripts.migrate`.
